ЯК ЗАПУСТИТИ

1. Розпакуй архів і відкрий папку KSE-Air-Alert-Forecast у VS Code або в терміналі.
2. Потрібен Python, рекомендовано 3.11 або новіший.
3. Виконай:

python -m pip install -r requirements.txt
python run.py check
python run.py backtest --assume-continuous-reporting

На macOS іноді потрібна команда python3 замість python.
За бажанням спочатку створи віртуальне середовище: python -m venv .venv.
Активація macOS/Linux: source .venv/bin/activate
Активація Windows PowerShell: .venv\Scripts\Activate.ps1

Перша команда встановлює залежності. Друга запускає тести й перевірку незалежності від майбутніх результатів. Третя відтворює історичне оцінювання.

--assume-continuous-reporting означає явне припущення про безперервність повідомлень. Архів не доводить повноту джерела. Без цього параметра прогнози не створюються.

Готові результати вже є в results: metrics.json, predictions.csv, backtest.png, data_quality.json, model_stability.json.

НОВИЙ ПРОГНОЗ НА ЗАВТРА

python run.py next-day --assume-continuous-reporting

Це потребує інтернету. Результат збережеться в results/next_day_forecast.json. Прогноз стосується кількості записаних початків тривог у Києві за повний наступний день. Це не передбачення конкретного удару і не заміна офіційних сповіщень. Якщо джерело недоступне чи застаріле, команда зупиниться, а не вигадуватиме дані.

ЯК ПЕРЕВІРИТИ РОБОТУ

Очікується успішне проходження 20 окремих тестів і повідомлення PASS для перевірки, що зміна пізніших результатів не змінює прогнози та вибір моделі. Історичний запуск обирає mean28. Його MAE на останніх 30 днях приблизно 1,24 записаного початку тривоги за день. Це не відсоток точності.

Для нових прогнозів результат залежить від дати та фактично доступних даних. Інтервал має номінальне покриття 80%, але воно не гарантоване для залежних часових рядів. Інтервали широкі, це чесно показано.

Повні пояснення й обмеження: README.md. Історичні дати є симуляціями. Фактичний час нового прогнозу записується окремо.
